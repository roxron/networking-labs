OSPF LAS Types:
!
> OSPF Link State Advertisements (LSAs) are how the specifics of routing protocol are sent between routers 
> LSAs are how the LSDB is Built 
> There three main types of LSAs that make up the topology database for an OSPF area 
> Others help advertise external routes into OSPF Domain 
!
> Type 1 LSA - Router 
  * Identifies routers within the area 
  * Advertises Rouer ID 
  * Also advertises any links from the roter and the neighbors on those links 
  * IF a DR is present, contains the IP address of the DR and a link to a transit network 
!
> Type 2 LSA - Network 
   * Only present if a DR has been elected on the interface 
   * Models a multi-access network with links to all the routers connected to that segmet 
   * Type 2 LSAs are only generated by DRs 
   * Conforms to the rules a link only has two nodes
!
> Type 3 LSA - Summary 
  * Generated by ABRs 
  * Cuts down ont Type 1 and 2 LSAs
  * Advertises the subnet and metric into the area 
  * Advertises with its own RID so other router know where to send traffic for the summarized network 
  * Not a summary route, but summarizes the T1/2 LSAs
!
> type 5 LSA - External 
  * Generated by ASBRs 
  * Advertises external routes into an area 
  * LSA is flooded to all * areas 
  * Comes in two flavors: 
     * E2 (default) - Static metric 
     * E1 - Adds internal metric to reach ASBR 
!
> Type 4 LSA - ASBR Advertisemenet 
    * Generated by ABRs 
    * Advertises routes to the ASBR outside the area 
!
OSPF AREA TYPES 
!
> OSPF routing domains are almost always broken into areas 
> Reduces complexity of the LSDB 
> Under normal circumstances standard area work perfectly 
> There are situations where a full LSDB/route table is not necessary 
!
> Standard area
  * Requires no extra configuration
  * Easiest to maintain, all routers know all routes 
  * Type 3 and type 5 LSAa are flooded through this area 
!
> Stub Area 
   * All routers in the area must be configured  
     * Area area-id stub 
   * Injectiong a default route for all external routes (E1/E2)
     * ABR drops types 5 LSAs 
   * Type 3 LSAs are flooded through this area, so you maintain internal routes 
   * Can not contain an ASBR 
> Configure:
   R1(config)# router ospf 10
   R1(config-router)# area 15 stub 
!
> Totally Stubby Area 
  * All routers in the area must be configured 
    * Area area-id stub no-summary 
  * Injects a default route for all inter-area routes 
    * ABR drops type 3 and 5 LSAs 
  * Can not contain an ASBR (no Type 5 LSAs) 
> Configure:
   R1(config)# router ospf 10
   R1(config-router)# area 15 stub no-summary 
!
> Not-so-Stubby Area (NSSA)
  * All routers in the area must be configured 
    * Area area-id nssa 
  * Acts like a stub area, except:
    * No default route (add default-information-originate) 
    * You can have an ASBR 
  * ASBR generates Type 7 LSAs, which the ABR Converts to Type 5
> Configure:
   R1(config)# router ospf 10
   R1(config-router)# area 15 nssa
!
> Totally Not-so-Stubby Area (NSSA)
  * All routers in the area must be configured 
    * Area area-id nssa no-summary 
  * Acts like an NSSA, except:
    * Deafault route injected for all Inter-area routes
    * You can have an ASBR 
  * ASBR genrates Type 7 LSAs, which the ABR converts to Type 5 
> Configure:
   R1(config)# router ospf 10
   R1(config-router)# area 15 nssa no-summary 
!

OSPF Route Summarization:
!
> As with EIGRP, you can create large "summary" routes
> Reduces the complexity of the routing rable 
> Unlike EIGRP, can only create summaries at ABRs and ASBRs (for external routes) 
  * All routers in the area must have the smae LSDB 
  * Summarization modifies the LSDB/routing table 
> Requires planning to properly implement 
!
> Internal summarization is done at the ABR using the command area area range subnet subnet-mask  
  * Where area is the that the individual routes are currently advertised in 
> This replace the multiple type 3 LSAs advertised with a single summarized Type 3 LSA 
!
Configure internal summary route:
! 
R1(config)# router ospf 10 
R1(config-router)# area 10 range 10.100.0.0 255.255.252.0 
!
!
> External summarization is done at the ASBR 
> Used to inject an external summary route into OSPF 
> Use the command summary-address subnet mask 
> Replaces multiple type 5 LSAs with a singe one 
!
Configure external summary route:
!
R1(config)# router ospf 10 
R1(Config-router)# summary-address 192.168.20.0 255.255.252.0 
!
R1# show ip ospf summary-address 
!
!

OSPF DEfault Route Propagation:
!
> OSPF, like EIGRP, allows you to specify a default route 
> Unlike EIGRP you cak specify a default route for a part or all of the network 
> Stub areas allow us to inject a default rote into specific area of the network 
> Route summarization to 0.0.0.0/0 at an ABR and ASBR will also work 
!
> However the easiest/most effective way is through the default-information originate command
 * Done at an ASBR 
 * Router must have a route to 0.0.0.0/0 
 * Creates a Type 5 LSA and floods it to the rest if the network 
 * Router withdraws the default route if the default route goes away 
!
> Can manipulate the metric value/type if you have multiple defailt routes 
> Can use the "always" keyword to advertise even if no defailt route exists 
!
Cofigure OSPF Default Route:
!
R1(config)# router ospf 10 
R1(config)# default-information-originate
